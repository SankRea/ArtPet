# ArtPet 代码结构

ArtPet 使用 Electron 主进程管理窗口、下载、配置与系统能力；渲染页面通过预加载脚本调用受限接口。运行时代码使用 CommonJS 和原生 HTML、CSS、JavaScript，打包沿用 electron-builder。

## 模块职责

| 路径 | 职责 |
| --- | --- |
| `src/main/index.cjs` | 组装服务，持有桌宠集合与运行状态，协调托盘、显示器变化、全屏休眠和退出保存 |
| `src/main/windows/` | 创建设置、桌宠、AI 对话和字幕窗口；统一窗口安全限制与图标来源 |
| `src/main/services/` | 模型目录与缓存、语音、AI 配置与请求、物理计算、用户数据位置 |
| `src/main/platform/windows/` | Windows 窗口几何检测、系统计时精度与登录启动 |
| `src/main/ipc/register.cjs` | 注册 IPC，校验发送窗口与主框架，路由至现有服务和动作 |
| `src/main/protocol.cjs` | 提供 `arkpet://` 本地资源，限制资源类型、主机和路径范围 |
| `src/main/paths.cjs` | 从源码位置计算应用根目录、预加载目录、页面目录和图标位置 |
| `src/preload/` | 按桌宠／设置、AI 对话、字幕三个页面用途暴露接口 |
| `src/renderer/` | 界面、动画与播放逻辑，不直接访问文件系统或原生系统接口 |
| `src/shared/product.cjs` | 从 `package.json` 读取公开名称与版本，集中保留兼容标识 |

窗口与服务仍通过明确的依赖参数协作。IPC 使用 `getLauncher()` 获取当前设置窗口，避免关闭并重新打开设置后仍信任旧窗口；可变的下载任务和所选桌宠由主入口提供操作函数。

## 路径与兼容

源码运行和 ASAR 内运行都由 `src/main/paths.cjs` 定位应用资源，不依赖启动命令的工作目录。预加载脚本、内置模型、PixiJS 文件与页面随程序打包；下载缓存和配置写入用户数据目录。

模型目录不随程序打包。`models.cjs` 从内置模型的 `assets/surtr/source.json` 建立最小列表；`ModelLibrary` 启动时恢复用户目录缓存和已下载模型，随后由主进程后台检查上游 `models_data.json` 的最新提交。首次获取自动完成，后续发现新版本只提示，用户拉取后才原子替换本地目录。更新与模型下载共用串行任务，保留已缓存模型的文件名和提交，避免下载中途改变资源路径。旧缓存缺少名称时先按 ID 恢复，获取目录后补齐。

公开名称为 ArtPet，以下标识继续保留：

| 标识 | 值 | 原因 |
| --- | --- | --- |
| 应用 ID | `local.arkpet.surtr` | 保持安装身份稳定，Windows AUMID 与打包配置一致 |
| 系统数据目录 | `%APPDATA%\ArkPet Surtr` | 沿用已有设置、模型、语音、AI 配置与 Electron 用户数据 |
| 便携数据目录 | 可执行文件旁的 `ArkPet-data` | 支持程序与数据一起移动 |
| 登录启动项名称 | `ArkPet Surtr` | 沿用已有注册名称 |
| 本地协议与页面桥接 | `arkpet://`、`window.arkpet` | 保持现有页面通信接口兼容 |

便携目录不可写时保留原有回退行为，并输出原因。便携程序移动或更换路径后，如需登录自动启动，应重新启用该设置，更新系统保存的可执行文件路径。

应用 ID、数据目录和启动项名称不能随展示名称一起替换。后续若调整数据目录，应另行设计迁移和失败恢复。

## 打包边界

`electron-builder.config.cjs` 只收集运行时代码、内置资源、图标、默认配置和第三方声明。`scripts/`、`test/`、下载缓存与开发工具不属于应用内容。生产依赖由 electron-builder 收集，Koffi 的原生模块解包到 ASAR 旁。

`build/icon.svg` 沿用原托盘的冰淇淋图形；`icon.png` 用于运行时，`icon.ico` 包含 16～256 像素多尺寸图标，用于 Windows 可执行文件与安装包。修改图标时需同步这些资源。

版本唯一来源为 `package.json`，产品模块、设置页和打包配置读取同一版本。发布前检查锁文件中的版本与依赖声明，标签必须为对应的 `v<版本号>`。

## 维护约定

修改 IPC 时同步对应预加载接口与调用页面，保留发送者校验。移动资源时同步 `paths.cjs` 和打包文件列表。调整模块路径时同步现有测试中的导入及主进程隔离运行环境。

现有回归测试位于 `test/`，覆盖设置保留、目录更新与缓存恢复，以及 Windows 全屏判断。构建和测试由维护者显式执行；提交代码本身不会触发构建工作流。
